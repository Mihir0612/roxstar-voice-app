- Backend plan marks auth as `NEEDS CLARIFICATION`.
- PDF does not define login.
- Result: Neither REST nor WebSocket authentication can be implemented.
- Required decision (Tech Manager): choose auth model (e.g. anonymous session, device-bound token, or provided credentials).

### C3. Spin Edge-Case Business Rules (Severity: CRITICAL)

Unresolved on backend:

- User leaves during spin.
- Admin disconnects during spin.
- Server restart during spin.
- Delayed-timer catch-up.

Frontend cannot render these states until backend rules are defined.

### C4. Event Payload Schemas Not Frozen (Severity: HIGH)

Backend proposes payloads but they are **not approved**. Frontend handlers cannot be written against unstable schemas.

### C5. Idempotency Transport Not Formalized (Severity: HIGH)

Frontend does not mention `Idempotency-Key`. Backend recommends it. Contract must be explicit, including key derivation and server replay behavior.

### C6. Reconnect Sequencing (Severity: MEDIUM)

Frontend: `DISCONNECTED → RECONNECTING → CONNECTED → room_state`.
Backend: `room_state` emitted on subscription.
Question: does the client re-subscribe, or does the server push on reconnect? Must be sequenced explicitly.

### C7. `eventId` Deduplication Adoption (Severity: MEDIUM)

Backend requires `eventId`. Frontend plan does not yet reference it. Frontend must adopt `eventId`-based dedupe.

### C8. Disconnect Grace Period Value (Severity: MEDIUM)

Backend `user_left` may fire on "detected disconnect" but grace period is undefined. Frontend UI must know when a user is "gone" vs. "reconnecting."
